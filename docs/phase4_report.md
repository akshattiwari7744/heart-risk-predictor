# Phase 4 Report - Backend API (FastAPI)

> **Educational/research prototype - not a medical device.** The API serves a model that estimates how likely a person with the
> submitted answers is to **report existing** coronary heart disease or a past heart attack, based on patterns in the **US** CDC BRFSS 2025
> survey. It does **not** predict a future heart attack, does **not** diagnose anyone, does **not** establish clinical risk, and may **not**
> generalise to people in India.

## Scope
Backend only. No frontend, no retraining, no changes to Phase 3 artifacts. The frozen model is loaded once at startup and used read-only.

## Files
**Created:** `api/__init__.py`, `api/settings.py`, `api/text.py`, `api/schemas.py`, `api/model_service.py`, `api/main.py`, `tests/test_api.py`, `docs/phase4_report.md`

## Endpoints
| Method | Path | Purpose |
|---|---|---|
| POST | `/predict` | Validates the 19 inputs; returns estimated probability, the frozen threshold, and the above/below result |
| GET | `/health` | API running? model loaded? (`status` is `ok` or `degraded`; a short `problem_code` when degraded) |
| GET | `/model-info` | Frozen model details, the 19 inputs with allowed ranges, target statement, disclaimer |
| GET | `/docs`, `/redoc`, `/openapi.json` | Swagger UI / ReDoc / OpenAPI (can be disabled with `API_ENABLE_DOCS=false`) |

### Inputs (all 19 required, exact order from `src/config.py`)
`age_group_5yr` (1-13), `sex_female` (0/1), `bmi` (12-99.99), `gen_health` (1-5), `phys_unhealthy_days` (0-30), `ment_unhealthy_days` (0-30),
`any_physical_activity` (0/1), `hypertension_told` (0/1), `high_cholesterol_told` (0/1), `diabetes_status` (1-4, category), `asthma_ever` (0/1),
`copd_ever` (0/1), `kidney_disease_ever` (0/1), `depression_ever` (0/1), `other_cancer_ever` (0/1), `smoker_status` (1-4, category),
`heavy_drinker` (0/1), `education_level` (1-4), `income_level` (1-7). Meanings are in `/docs` and `/model-info`.

**Validation policy:** strict. Whole numbers where whole numbers are expected (text, `true/false`, decimals and `null` are rejected), `bmi` any finite number
in range, unknown fields rejected, NaN/Infinity rejected, bodies over 16 KB rejected. There is deliberately **no** "unknown/missing" option: the model would
silently fill gaps with training-population values, so the API refuses instead. Errors name the field and the allowed values and never echo the submitted value.

### Response (`/predict`)
`estimated_probability` (calibrated), `decision_threshold` (read from the saved model, never recomputed), `above_threshold` (`probability >= threshold`),
`result_label`, `interpretation`, `target`, `model` (name, calibration, training mode, data source), `disclaimer`, `request_id`.

## Startup checks (fail-closed)
The model is loaded once. It is served only if: all three artifact files exist and are readable; SHA-256 of `model.joblib` matches `model_meta.json`;
scikit-learn matches the training version; training mode is not `quick` (labelled, or inferred from `cfg` for older artifacts; override with
`API_ALLOW_QUICK_MODEL=true`); the object is a `FinalModel`; feature order is identical in config, model, metadata and API schema; threshold, model name and
calibration agree between model and frozen decisions; and one self-test prediction succeeds. Otherwise the API still starts, `/health` reports `degraded`
with a short code, and `/predict` returns a generic 503. Details (including paths) go only to the server log.

## Security and privacy defaults
- **CORS:** default `API_ENV=production` => no cross-origin access. Set `API_CORS_ORIGINS=https://your-frontend.example` (comma-separated, explicit origins only).
  `*` is rejected in every mode. `API_ENV=development` defaults to `localhost`/`127.0.0.1` on ports 5173 and 3000. Credentials are never allowed.
- **Errors:** uniform JSON `{error, message, request_id}`; no stack traces, file paths, or submitted values in responses. Full tracebacks are logged server-side with the request id.
- **Logging:** request id, method, path, status, latency, and the above/below result. **Health answers are never logged or stored.**
- **Headers:** `X-Request-ID` (client value accepted only if it matches `[A-Za-z0-9-]{8,64}`), `X-Content-Type-Options`, `Referrer-Policy`, `Cache-Control: no-store` on `/predict`, restrictive CSP on API routes.

## Limitations
- **Research prototype.** Self-reported US survey data; existing-condition target; association, not causation or future risk; not validated for India.
- The decision threshold favours catching reported cases, so many people above it will not have reported heart disease; below it is not reassurance.
- **No authentication or rate limiting.** Do not expose publicly without a reverse proxy providing TLS, rate limits, and access control.
- Body-size limit uses the `Content-Length` header; chunked uploads without it are not capped by the app.
- `joblib` loads a pickle: only serve artifacts you produced. The hash check detects accidental change, not a malicious attacker who can also edit the metadata.
- Swagger UI normally loads its assets from a public CDN, so `/docs` may not render offline; `/openapi.json` always works.
- Starlette's test client currently warns that `httpx` is deprecated in favour of `httpx2`; harmless today, but revisit when upgrading.
- Single model, single-row predictions, no persistence.
